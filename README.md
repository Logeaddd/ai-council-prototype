# AI Council 使用说明

AI Council 是一个本地运行的 AI 圆桌工具。

简单说，就是你建一个“小组”，给里面的几个 AI 配好模型和角色，然后让它们围着一个问题讨论。你可以让某个 AI 负责写方案，让另一个 AI 负责挑问题，也可以只放一个 AI 当普通助手用。

现在还是初代 demo。能用，但不算精装修软件。

## 能做什么

- 多个 AI 一起讨论一个问题。
- 每个 AI 可以单独配置模型、API Key、角色名和头像。
- 可以把某个 AI 设成“审查者”。审查者就是专门挑问题的人。
- 审查强度可以选 1 到 3。1 比较宽松，3 会挑得细。
- 支持私聊。私聊内容只会进对应 AI 的上下文，其他 AI 看不到正文。
- 支持 DeepSeek、OpenAI、OpenRouter、SiliconFlow，也可以填自定义 API 地址。
- 可以检测模型列表。检测不到也能手动填模型名。
- 会记录每次讨论的结论、风险、下一步。
- 有用量统计，大概看每个成员用了多少输入和输出 token。token 可以理解成模型收费和上下文长度用的“字数单位”。
- 支持文件提议和审批。AI 不能直接乱写你电脑文件，只能先提议，本地程序再按权限处理。

## 适用系统

主要给 Windows 用。

我自己按 Windows 11 测的。Windows 10 理论上也能跑。

如果你是 macOS 或 Linux，先按开发者方式跑源码，打包版本暂时别指望开箱即用。

## 下载后怎么打开

下载 `AI-Council-Portable.zip`。

解压出来。注意，是解压，不要在压缩包里直接双击。

进入文件夹：

```text
AI-Council-Portable
```

双击：

```text
AI-Council.exe
```

如果打不开，也可以试试双击：

```text
AI-Council.bat
```

这个 bat 会把部分错误留在窗口里，方便看问题。这里容易忽略，很多人双击 exe 闪退后就不知道发生了什么。

## 第一次打开先做什么

左边是小组列表。

第一次一般先新建小组：

1. 点左上角的小组加号。
2. 填小组名，比如 `demo`。
3. 选所有小组保存的文件夹。
4. 点创建。

小组文件夹就是 AI Council 放配置、讨论记录、私聊记录的地方。建议放在你能找到的位置，比如：

```text
D:\AI-Council-Groups
```

别放到系统目录。也别放到微信临时文件夹里。微信目录经常清缓存，路径还很长，后面排查问题很烦。

## 配 AI 席位

圆桌上每个头像就是一个席位。席位可以理解成“一个 AI 成员”。

右键席位，点“修改 API 配置”。

常用字段这样填：

- Provider：模型供应商，比如 DeepSeek、OpenAI。
- API URL：接口地址。选了 Provider 后可以点“使用官方 URL”。
- API Key：你的模型密钥。它就是调用模型的钥匙，不要发给别人。
- 模型名：比如 `deepseek-chat`。
- 权限：这个 AI 能不能提出文件操作。
- 角色名称：比如“方案设计”“审查者”“总结者”。

填完可以点“检查连接”。如果想看这个供应商有哪些模型，点“检测模型”。

检测模型失败不一定代表不能用。有些供应商不开放模型列表，手动填模型名也可以。

## API URL 常用值

软件里已经预设了几个：

```text
DeepSeek     https://api.deepseek.com/v1
OpenAI       https://api.openai.com/v1
OpenRouter   https://openrouter.ai/api/v1
SiliconFlow  https://api.siliconflow.cn/v1
```

如果你用的是别的中转站，就选自定义，然后填对方给你的 URL。

小提醒：很多报错不是 key 错，而是 URL 少了 `/v1`。先检查这个。

## 开始一次讨论

右下角输入你的问题，点发送。

比如：

```text
帮我设计一个个人阅读记录软件，要求简单可做，列出功能和风险。
```

上方可以调“自主轮次”。这表示最多让 AI 们来回说几轮。

简单问题别开太大，3 到 5 轮够了。复杂方案可以开高一点。轮次越多，花的钱和时间也越多。

讨论中可以暂停，也可以全体停止。

## 审查者怎么用

在席位配置里勾选“设为审查者”。

审查强度：

- 1：只抓明显大问题。适合小问题、简单代码、日常问答。
- 2：会看关键细节。适合普通产品方案、一般代码。
- 3：比较严格。适合安全、架构、长期项目。

不要所有问题都开 3。真的会变慢，也会变贵。

我自己的经验是：简单问题用 1，中等方案用 2。只有你真想被狠狠审，才用 3。

## 私聊

每个 AI 头像旁边有私聊按钮。

私聊发出去后，只有这个 AI 下次发言时能看到。公共对话区只会提示“已私聊某某”，不会把正文公开。

适合这种情况：

```text
你下一轮重点检查成本，不要展开 UI。
```

私聊不是即时聊天窗口。它更像给某个 AI 单独塞一条额外指令。

## 全局要求

顶部有“全局要求”。

这里写的是所有 AI 都要遵守的规则，比如：

```text
回答尽量短，先给可执行方案，不要过度扩展范围。
```

如果你发现 AI 老跑题，先改这里。

## 权限是什么

权限分三档：

- 文本：只能说话，不能提文件操作。
- 工具：可以提出文件操作，但需要你批准。
- 完全：满足安全规则后可以自动执行部分文件操作。

这里的“文件操作”就是新建、修改、追加、删除文件。

默认建议用“文本”。要让 AI 改文件时，再给特定席位开工具或完全权限。

工具和完全权限需要 Git。Git 可以理解成文件修改记录器。每次写文件都会留下 commit，方便回滚。没有 Git 的小组不要开这些权限。

## 会议决议和文件提议

讨论结束后，右上功能区里可以看“会议决议”。

决议里会有：

- 最终回答
- 风险
- 下一步
- 是否已经能执行

如果 AI 提了文件操作，也会出现在文件提议里。

别把“保存结论”当成“执行文件修改”。保存只是留档，不会动你的项目文件。

## 常见问题

### 双击 exe 报 Cannot find module index.js

这是旧打包版本的问题。

换最新的 `AI-Council-Portable.zip`。新版已经把 Electron 入口改好了。

### 窗口打开了，但模型一直不可用

先右键席位，检查 API 配置。

重点看三项：

- API Key 有没有填错。
- API URL 是否带 `/v1`。
- 模型名是不是供应商支持的。

可以点“检查连接”。如果提示认证失败，一般就是 key 不对或账号没额度。

### 检测模型失败

不一定是大问题。

有些供应商的 `/models` 接口不稳定，或者中转站不支持模型列表。手动填模型名再试。

### 讨论很慢

常见原因：

- 席位太多。
- 轮次太高。
- 审查强度太高。
- 模型本身慢。

先把轮次调到 3，把审查强度调到 1 或 2。

### 钱花得比想象多

多 AI 讨论本来就比单 AI 贵。

这个工具的重点不是“省 token”，而是让多个角色互相补漏、保留过程、把风险说清楚。

如果只是问一句小事，直接用一个 AI 更省。

### 文件权限开不了

检查小组文件夹是不是 Git 仓库。

如果你不懂 Git，先别急着开工具权限。普通讨论不需要它。

### 解压后打不开

确认不是在压缩包里运行。

再确认整个文件夹都在，不要只拷走 `AI-Council.exe`。这个程序需要旁边的 `resources`、`locales`、dll 文件一起在。

### Windows 提示不安全

这是因为 demo 版没有代码签名。

你信任来源的话，点“更多信息”，再点“仍要运行”。不信任就别运行。

## 开发者运行

如果你不是用 exe，而是跑源码：

```bash
cd prototype
npm install
npm run desktop
```

打包 portable：

```bash
cd prototype
npm run desktop:portable
```

打包产物在：

```text
prototype/dist/AI-Council-Portable.zip
```

## 数据放在哪里

软件会把小组数据放在你选择的小组文件夹里。

里面可能有：

- 小组配置
- 对话记录
- 私聊记录
- 用量记录
- 文件提议和审批记录

这些东西可能包含你的问题、模型输出、项目路径。发给别人前先看一眼，别把自己的工作内容打包出去。

## 现在的状态

这是能试用的初代 demo。

适合拿来试：

- 多 AI 讨论产品方案
- 让审查者帮你找风险
- 对比不同角色的回答
- 体验私聊、模型检测、圆桌界面

不建议现在就拿它管重要生产文件。文件写入那块虽然做了审批和 Git 记录，但还是早期功能。先用测试项目试。
